## 本次核心覆盖

### 表格边框

使用实际 renderer 代码，模拟每个单元格独立的六条边：确认只开竖边框时仅显示行号分隔线；横边框仅内横线；外框仅周界；全部八种组合的共享边一致；没有行号时不生成额外竖线；单行单列正确区分内部与周界；对角线关闭。

测试“仅应用边框”前后文字、字体、字号、字色、填色、尺寸和窗口保留；普通高亮排版亦遵从边框设置。旧有逐行表格、动态行号宽度、窗口组合与失败清理模拟用例仍通过。

这些检查不证明 Office 中的最终线宽、抗锯齿、主题对比度、表格样式优先级或合并单元格行为；需在 PowerPoint 中目测。

### 界面与作者

调用实际 GetCustomUI 与 IDispatch 回调，核验窗口大按钮、开启/关闭标签、控件灰显、参数保留、背景优先关系、边框偏好持久化。“关于”响应中包含 Iceriny、0.3.1、位数和日志状态；安装应用的发布者同样标注 Iceriny。

静态核验 7 个 Ribbon 组、86 个唯一 ID、75 种 Ribbon 回调、81 个分发表方法，回调名与 DISPID 枚举顺序匹配。检查显式/动态属性互斥、窗口控件归组及长状态标签移除。**不是完整 CustomUI XSD 验证，也未实际渲染 Office Ribbon**；不同窗口宽度、Office 主题与显示缩放下的外观待实机检查。

### 日志

实际原生日志函数在默认关闭时不获取日志目录、不打开或追加日志文件；显式开启后记录事件，关闭立即停止。注册表重连保留选择，打开/清理日志不会暗中启用记录。

实际 bridge 入口运行错误请求时，默认不创建错误日志；启用后只记录时间、类别/错误码，未持久化样例代码、报错堆栈或路径；随后关闭不追加。日志写入失败不妨碍返回正常错误信息。

安装器的 PowerShell Diagnostics 参数与 npm 禁用日志参数已静态核对，但没有实际执行 Windows PowerShell 下载/npm 安装，因此不把安装阶段零日志行为列为实机通过。系统/Office 自身的事件日志、正常依赖与缓存数据不由插件诊断开关控制。
